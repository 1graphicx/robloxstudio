Chapitre 00 — Jour 1

L'interface de Roblox Studio

Avant d'écrire une seule ligne de code, repère les quatre panneaux que tu vas utiliser en permanence.

Explorer — la liste de tous les objets de ton jeu (Workspace, ServerScriptService, joueurs...). C'est ton arborescence de fichiers.
Propriétés — les réglages de l'objet sélectionné dans l'Explorer : sa position, sa couleur, sa taille.
Éditeur de scripts — l'endroit où tu écris le code Lua. Il s'ouvre quand tu double-cliques sur un Script.
Sortie (Output) — affiche ce que ton code imprime avec print(), et les erreurs si quelque chose plante. Garde toujours un œil dessus.

Pour créer ton premier script : clic droit sur ServerScriptService dans l'Explorer → Insert Object → Script. Une fenêtre d'édition s'ouvre, prête à recevoir du Lua.

Chapitre 01 — Jour 1

Variables et types

Une variable stocke une valeur sous un nom que tu choisis. En Lua, on la déclare avec local.

local nomJoueur = "Astro"      -- une chaîne de texte (string)
local vie = 100                -- un nombre (number)
local estVivant = true         -- un booléen (boolean)

print(nomJoueur)
print(vie)
print(type(vie))
SORTIE
Astro
100
number
Astuce — utilise toujours local. Une variable globale (sans local) est visible partout dans le script et peut créer des bugs difficiles à trouver.
Chapitre 02 — Jour 1

Les conditions

Avec if, ton script prend une décision selon une condition.

local vie = 25

if vie <= 0 then
    print("Le joueur est éliminé")
elseif vie < 30 then
    print("Attention, vie basse !")
else
    print("Tout va bien")
end
SORTIE
Attention, vie basse !
Piège classique — en Lua, on compare avec == (deux signes égal). Un seul = sert uniquement à donner une valeur à une variable.
Chapitre 03 — Jour 2

Les boucles

Une boucle répète du code sans que tu aies à le recopier.

-- répéter un nombre de fois précis
for i = 1, 5 do
    print("Tour numero " .. i)
end

-- répéter tant qu'une condition reste vraie
local piecesRestantes = 3
while piecesRestantes > 0 do
    print("Encore " .. piecesRestantes .. " piece(s)")
    piecesRestantes = piecesRestantes - 1
end
SORTIE
Tour numero 1
Tour numero 2
Tour numero 3
Tour numero 4
Tour numero 5
Encore 3 piece(s)
Encore 2 piece(s)
Encore 1 piece(s)
Chapitre 04 — Jour 2

Les fonctions

Une fonction regroupe un bloc de code que tu peux réutiliser autant de fois que tu veux, avec des valeurs différentes à chaque fois.

local function saluer(nom)
    return "Bienvenue, " .. nom .. " !"
end

print(saluer("Astro"))

local function ajouterVie(vieActuelle, bonus)
    return vieActuelle + bonus
end

print(ajouterVie(50, 20))
SORTIE
Bienvenue, Astro !
70
Astuce — return renvoie une valeur hors de la fonction. Sans return, la fonction ne renvoie rien du tout (nil).
Chapitre 05 — Jour 2

Les tables

La table est la structure la plus utilisée en Lua : elle sert aussi bien de liste que de dictionnaire.

-- une liste (tableau indexé, la 1ere case est le numero 1)
local inventaire = {"Epee", "Bouclier", "Potion"}
print(inventaire[1])

-- un dictionnaire (cle -> valeur)
local joueur = {
    nom = "Astro",
    vie = 100,
    niveau = 3
}
print(joueur.nom)
print(joueur.vie)
SORTIE
Epee
Astro
100
Chapitre 06 — Jour 3

Services et instances Roblox

Un jeu Roblox est un arbre d'objets (des « instances »). Les Services sont des instances spéciales, déjà présentes dans chaque jeu, qui donnent accès aux grandes fonctionnalités du moteur.

-- game:GetService recupere un service integre a Roblox
local Players = game:GetService("Players")
local Workspace = game:GetService("Workspace")

-- script.Parent = l'objet dans lequel CE script est place
local part = script.Parent
print(part.Name)
Astuce — script.Parent est l'une des lignes les plus utilisées en Roblox : elle veut dire « l'objet qui contient ce script ».
Chapitre 07 — Jour 3

Position, taille et couleur

Les objets 3D de Roblox (les « Parts ») ont des propriétés que ton code peut lire et modifier en direct.

local part = script.Parent

part.Position = Vector3.new(0, 10, 0)      -- X, Y, Z
part.Size = Vector3.new(4, 4, 4)
part.Color = Color3.fromRGB(255, 60, 60)   -- rouge
Astuce — Color3.fromRGB() prend trois nombres de 0 à 255 (rouge, vert, bleu). C'est la méthode moderne recommandée pour choisir une couleur précise.
Fais glisser pour tourner autour de la Part.
Chapitre 08 — Jour 4

Les événements

Un événement déclenche du code automatiquement quand quelque chose se produit : un contact, un clic, un timer.

local part = script.Parent

local function onTouch(autreObjet)
    print(autreObjet.Name .. " a touche la Part !")
end

part.Touched:Connect(onTouch)
Script vs LocalScript — un Script s'exécute sur le serveur : il gère les règles du jeu, valables pour tout le monde. Un LocalScript s'exécute sur l'ordinateur d'un seul joueur : il gère l'interface et les boutons. 
-- dans un LocalScript, a l'interieur d'un TextButton
local bouton = script.Parent

local function onClick()
    print("Bouton clique !")
end

bouton.MouseButton1Click:Connect(onClick)
Chapitre 09 — Jour 4

Animer avec TweenService

TweenService fait passer une propriété d'une valeur à une autre en douceur, au lieu d'un changement brutal.

local TweenService = game:GetService("TweenService")
local part = script.Parent

local infos = TweenInfo.new(2, Enum.EasingStyle.Sine)
local objectif = { Position = Vector3.new(0, 15, 0) }

local animation = TweenService:Create(part, infos, objectif)
animation:Play()
Le cube monte en 2 secondes, comme le ferait TweenService.
Chapitre 10 — Jour 5

Mini-projet : une porte automatique

On assemble tout : un événement, une condition et une animation, pour construire une vraie mécanique de jeu.

local porte = script.Parent
local TweenService = game:GetService("TweenService")
local Players = game:GetService("Players")

local infosTween = TweenInfo.new(0.5)
local objectifOuvert = { CFrame = porte.CFrame * CFrame.new(0, 10, 0) }

local function ouvrirPorte(autreObjet)
    local joueur = Players:GetPlayerFromCharacter(autreObjet.Parent)
    if joueur then
        local tween = TweenService:Create(porte, infosTween, objectifOuvert)
        tween:Play()
    end
end

porte.Touched:Connect(ouvrirPorte)
Comment le lire — Touched se déclenche dès qu'un objet touche la porte. On vérifie que c'est bien un joueur avec GetPlayerFromCharacter, puis on anime le CFrame de la porte pour la faire glisser vers le haut.
À toi de jouer — dans Roblox Studio, crée une Part nommée « Porte », colle ce script dedans, et teste en marchant dessus.
Chapitre 11 — Jour 6

Debounce et cooldown propres

L'événement .Touched peut se déclencher des dizaines de fois par seconde pour un seul contact. Sans protection, ta porte s'anime 30 fois d'affilée, tes pièces se multiplient, etc. La solution : un debounce.

Le problème — Sans debounce, chaque partie du personnage qui touche la Part déclenche l'événement séparément : bras gauche, bras droit, tête... .Touched peut tirer 30 × en une seconde pour un seul joueur. 
-- [MAUVAIS] SANS debounce — déclenche des dizaines de fois
local part = script.Parent
part.Touched:Connect(function(hit)
    print("Touché !") -- affiche 30 fois/sec
end)
-- [BON] AVEC debounce par table (multi-joueurs)
local Players = game:GetService("Players")
local part = script.Parent

local cooldowns = {} -- { [userId] = true }

local function onTouch(hit)
    local joueur = Players:GetPlayerFromCharacter(hit.Parent)
    if not joueur then return end      -- pas un joueur
    if cooldowns[joueur.UserId] then return end -- déjà en cooldown

    cooldowns[joueur.UserId] = true
    print(joueur.Name .. " a touché la Part !")

    task.delay(2, function()           -- libère après 2 secondes
        cooldowns[joueur.UserId] = nil
    end)
end

part.Touched:Connect(onTouch)

-- Nettoie la table quand le joueur quitte
Players.PlayerRemoving:Connect(function(joueur)
    cooldowns[joueur.UserId] = nil
end)
task.wait() vs task.delay() vs task.spawn()

task.wait(2) — bloque le thread actuel pendant 2 s. Dangereux dans un event Touched partagé : les autres joueurs attendent que le thread soit libéré.

task.delay(2, fn) — planifie l'exécution de fn dans 2 s dans un nouveau thread. Le thread actuel continue. Parfait pour le cooldown.

task.spawn(fn) — lance fn immédiatement dans un nouveau thread, sans attendre.
À toi de jouer — Crée une Part "Piège" dans Studio. Connecte-la à .Touched. Sans debounce, affiche combien de fois elle se déclenche en 1 seconde avec un compteur. Puis ajoute le debounce et observe la différence.
Chapitre 12 — Jour 7

CFrame et Vector3 en profondeur

Position dit où est l'objet. CFrame dit où il est et dans quelle direction il regarde. Un CFrame, c'est une boussole + une position fusionnées en un seul objet.

Analogie : imagine que tu es un soldat sur une carte.
• Position = ta case sur la carte (x, y, z)
• CFrame = ta case + la direction où tu regardes (nord, sud, est, ouest…)
La Part a pivoté : Position ne change pas, mais le CFrame intègre la rotation.
local part = script.Parent

-- Position = seulement le vecteur XYZ
part.Position = Vector3.new(0, 5, 0)

-- CFrame = position + orientation
part.CFrame = CFrame.new(0, 5, 0)          -- même position, rotation nulle
part.CFrame = CFrame.new(0, 5, 0) * CFrame.Angles(0, math.rad(45), 0)
-- La Part est à (0,5,0) ET tournée de 45° sur l'axe Y
-- Multiplication de CFrame : se déplacer "devant" soi
-- (repère local, pas monde)
local part = script.Parent

-- "Avance de 5 unités dans la direction où la Part regarde"
part.CFrame = part.CFrame * CFrame.new(0, 0, -5)
-- Note : en Roblox, Z négatif = "devant" par défaut
-- PivotTo : déplacer tout un Model d'un coup
local model = workspace.MaVoiture   -- un Model avec un PrimaryPart

-- Mauvais : déplace seulement le PrimaryPart, pas les autres pièces
model.PrimaryPart.CFrame = CFrame.new(10, 0, 10)

-- Bon : déplace tout le Model ensemble
model:PivotTo(CFrame.new(10, 0, 10))
Piège physique — Si une Part a de la physique active (non ancrée), changer son .CFrame la téléporte brutalement au lieu de la déplacer. Les objets en collision passent à travers des murs. Pour les objets physiques, utilise AssemblyLinearVelocity (chapitre 13) à la place.
À toi de jouer — Crée une Part ancrée dans Studio. En Script, écris une boucle for qui exécute 8 fois : part.CFrame = part.CFrame * CFrame.new(0, 0, -2) avec un task.wait(0.5) entre chaque. Observe la Part glisser "devant" elle-même, quelle que soit sa rotation initiale.
Chapitre 13 — Jour 8

Physique : vélocité et AssemblyLinearVelocity

Deux façons de "bouger" un objet : le téléporter (changer son CFrame directement) ou lui donner une impulsion physique (comme pousser une balle). La deuxième respecte les collisions.

Analogie : téléportation vs lancer.
• Changer le CFrame = attraper un cube et le poser ailleurs — il traverse les murs.
• AssemblyLinearVelocity = lui donner une poussée — il rebondit, tombe, suit la physique. 
local part = script.Parent

-- Méthode 1 : téléportation (ignore la physique)
part.CFrame = CFrame.new(0, 10, 0)  -- passe à travers les murs !

-- Méthode 2 : vélocité physique (respecte les collisions)
part.Anchored = false   -- la Part doit être non-ancrée
part.AssemblyLinearVelocity = Vector3.new(0, 50, 0)
-- La Part monte à 50 unités/sec sur Y, puis retombe sous la gravité
-- PrimaryPart : obligatoire pour la physique d'un Model entier
-- Sans PrimaryPart, Roblox ne sait pas "quel centre" déplacer.
local vehicule = workspace.Vehicule
vehicule.PrimaryPart = vehicule.Chassis   -- désigne le centre

-- Calcul manuel d'une vélocité depuis deux positions
-- (utile pour mesurer la vitesse d'un objet)
local pos1 = part.Position
task.wait(0.1)
local pos2 = part.Position
local dt = 0.1

local vitesse = (pos2 - pos1) / dt
-- vitesse est un Vector3 : vitesse.Magnitude donne la valeur en u/s
print("Vitesse : " .. vitesse.Magnitude .. " u/s")
À toi de jouer — Crée une Part non-ancrée dans Studio. En Script, attend que le jeu tourne, puis donne-lui AssemblyLinearVelocity = Vector3.new(20, 40, 0). Observe : elle monte en arc, ralentit, retombe (gravité !). Compare avec CFrame = CFrame.new(20, 40, 0) et remarque la différence.
Chapitre 14 — Jour 9

RunService.Heartbeat et deltaTime (dt)

RunService.Heartbeat appelle ton code à chaque frame de simulation. C'est l'endroit où faire des calculs physiques, déplacements continus, ou vérifications actives — sans boucle while infinie.

Pourquoi dt et pas un nombre fixe ?
Si tu déplaces un objet de 5 unités par frame et que le jeu ralentit de 60 fps à 30 fps, l'objet se déplace deux fois moins vite. En multipliant par dt (temps écoulé depuis la dernière frame), la vitesse reste constante quelle que soit la performance. 
local RunService = game:GetService("RunService")
local part = script.Parent

-- [MAUVAIS] Vitesse dépendante du FPS — se déplace 2x moins vite à 30 fps
RunService.Heartbeat:Connect(function(dt)
    part.Position += Vector3.new(0.05, 0, 0)  -- 0.05 par frame, pas par seconde
end)

-- [BON] Vitesse indépendante du FPS — 3 unités PAR SECONDE, toujours
local VITESSE = 3
RunService.Heartbeat:Connect(function(dt)
    part.Position += Vector3.new(VITESSE * dt, 0, 0)
end)
-- Connexion / déconnexion propre (éviter les fuites mémoire)
local connexion = nil  -- stocke la connexion dans une variable

connexion = RunService.Heartbeat:Connect(function(dt)
    -- ... logique de déplacement ...
    if conditionDArret then
        connexion:Disconnect()   -- coupe la boucle
        connexion = nil          -- libère la référence
    end
end)
Heartbeat vs Stepped vs RenderStepped
• Heartbeat — après la simulation physique. Pour déplacer des objets côté serveur.
• Stepped — avant la simulation physique. Pour modifier des forces avant qu'elles soient calculées.
• RenderStepped — côté client uniquement, avant le rendu. Pour les effets visuels ou la caméra.
À toi de jouer — Crée une Part ancrée. Connecte un Heartbeat qui accumule le temps total écoulé (tempsTotal = tempsTotal + dt). Quand tempsTotal > 5, déconnecte et affiche "5 secondes écoulées". Teste : c'est plus fiable qu'un task.wait(5) dans une boucle.
Chapitre 15 — Jour 10

Humanoid avancé

Le Humanoid est le "cerveau moteur" d'un personnage Roblox. Il expose des propriétés riches pour détecter exactement ce que fait un joueur : saute-t-il ? court-il ? tombe-t-il ?

-- Obtenir le Humanoid d'un joueur qui rejoint
local Players = game:GetService("Players")

Players.PlayerAdded:Connect(function(joueur)
    joueur.CharacterAdded:Connect(function(character)
        local humanoid = character:WaitForChild("Humanoid")

        -- Lire l'état actuel
        local etat = humanoid:GetState()
        print(etat)   -- ex : Enum.HumanoidStateType.Running

        -- Les états importants :
        -- Enum.HumanoidStateType.Running
        -- Enum.HumanoidStateType.Jumping
        -- Enum.HumanoidStateType.Freefall  (chute libre)
        -- Enum.HumanoidStateType.Landed
        -- Enum.HumanoidStateType.Swimming
        -- Enum.HumanoidStateType.Dead
    end)
end)
-- Appliquer une vélocité horizontale au saut sans casser le Y
-- Mauvais : écrase la vélocité verticale du saut
local rootPart = character:FindFirstChild("HumanoidRootPart")

humanoid.Jumping:Connect(function(isJumping)
    if isJumping then
        -- [MAUVAIS] Écrase le Y, le joueur ne monte plus
        rootPart.AssemblyLinearVelocity = Vector3.new(20, 0, 0)

        -- [BON] Conserve le Y existant, ajoute seulement le X
        local v = rootPart.AssemblyLinearVelocity
        rootPart.AssemblyLinearVelocity = Vector3.new(20, v.Y, 0)
    end
end)
À toi de jouer — Connecte-toi à humanoid.StateChanged et affiche dans la console le nom de chaque nouvel état quand le joueur court, saute, et atterrit. Tu dois voir la séquence : Running → Jumping → Freefall → Landed.
Chapitre 16 — Jour 11

OverlapParams et détection de zone

.Touched se déclenche une fois au premier contact. Mais si tu veux savoir en permanence quels objets sont dans une zone (comme une salle de téléportation), tu veux une vérification active par zone.

Touched vs zone active
• .Touched — événement instantané au premier contact physique. Peut rater si l'objet téléporte dedans.
• GetPartsInPart / GetPartBoundsInBox — vérification active à chaque frame : liste tous les objets qui se chevauchent avec la zone, même s'ils sont apparus dedans sans "toucher" les bords. 
local workspace = game:GetService("Workspace")
local zone = workspace.ZoneDetection   -- une Part qui sert de "capteur"

-- Configurer les paramètres de recherche
local params = OverlapParams.new()
params.FilterType = Enum.RaycastFilterType.Include
-- Include : ne cherche QUE dans les descendants listés
-- Exclude : cherche partout SAUF dans les descendants listés
params.FilterDescendantsInstances = {workspace.Players} -- zone à inspecter

-- À chaque frame : liste les Parts dans la zone
local RunService = game:GetService("RunService")
RunService.Heartbeat:Connect(function()
    local parts = workspace:GetPartsInPart(zone, params)
    for _, part in ipairs(parts) do
        -- est-ce un personnage joueur ?
        local humanoid = part.Parent:FindFirstChildOfClass("Humanoid")
        if humanoid then
            print(part.Parent.Name .. " est dans la zone")
        end
    end
end)
-- Variante : zone définie par une boîte (sans Part physique)
local centre = CFrame.new(0, 5, 0)
local taille = Vector3.new(10, 6, 10)

local parts = workspace:GetPartBoundsInBox(centre, taille)
for _, part in ipairs(parts) do
    print(part.Name)
end
À toi de jouer — Crée une grande Part transparente (Transparency = 0.8, CanCollide = false) nommée "Zone". En Heartbeat, affiche dans la console le nombre de Parts qui se trouvent à l'intérieur à chaque frame. Marche, saute dans la zone, observe le nombre changer.
Chapitre 17 — Jour 12

TweenService avancé

Au-delà de tweener une Part directement, on peut tweener un NumberValue et lire sa valeur intermédiaire pour contrôler n'importe quoi — musique, caméra, interface — sans coupler l'animation à l'objet.

-- Tweener un NumberValue pour découpler "valeur" et "objet"
local TweenService = game:GetService("TweenService")

local valeur = Instance.new("NumberValue")
valeur.Value = 0
valeur.Parent = script  -- le mettre quelque part pour qu'il existe

local infos = TweenInfo.new(3, Enum.EasingStyle.Sine)
local tween = TweenService:Create(valeur, infos, {Value = 100})
tween:Play()

-- Lire la valeur pendant l'animation
valeur.Changed:Connect(function(newVal)
    -- Tu peux utiliser newVal pour tout : volume, taille, opacité...
    workspace.Speaker.Volume = newVal / 100
    print("Volume actuel : " .. newVal)
end)
-- Pause, Play, Cancel et relancer un tween
local tween = TweenService:Create(part, TweenInfo.new(5), {Position = Vector3.new(0,10,0)})

tween:Play()

task.wait(2)
tween:Pause()   -- gèle l'animation là où elle en est

task.wait(1)
tween:Play()    -- reprend depuis l'endroit où elle était gelée

-- Cancel réinitialise le tween (repart de zéro au prochain Play)
tween:Cancel()
tween:Play()    -- repart du début
-- Nettoyer après un tween avec .Completed
local tween = TweenService:Create(part, TweenInfo.new(2), {Transparency = 1})

local connexion
connexion = tween.Completed:Connect(function(etat)
    if etat == Enum.PlaybackState.Completed then
        part:Destroy()        -- supprime la Part après qu'elle disparaît
        connexion:Disconnect() -- coupe l'événement pour éviter la fuite
        connexion = nil
    end
end)
tween:Play()
À toi de jouer — Crée un IntValue (valeur 0). Tweene-le vers 10 en 3 secondes. Dans Changed, synchronise la WalkSpeed d'un Humanoid avec cette valeur × 2. Le joueur accélère progressivement en 3 secondes.
Chapitre 18 — Jour 13

Machines à états simples (state machines)

Quand un système peut être dans plusieurs modes exclusifs (porte ouverte/fermée, perceuse activée/arrêtée, joueur invincible/normal), empiler des if crée des bugs imprévisibles. Une state machine résout ça.

Le problème sans state machine — Si un joueur appuie deux fois rapidement sur "Ouvrir", deux tweens partent en même temps, et la porte finit dans une position aléatoire. 
-- Exemple : porte avec state machine booléenne
local TweenService = game:GetService("TweenService")
local porte = script.Parent
local Players = game:GetService("Players")

-- L'état de la porte : UN seul peut être vrai à la fois
local estOuverte = false
local estEnMouvement = false   -- VERROU : bloque les actions pendant l'animation

local posFermee = porte.CFrame
local posOuverte = porte.CFrame * CFrame.new(0, 10, 0)

local function ouvrir()
    if estEnMouvement or estOuverte then return end  -- bloque si déjà en cours
    estEnMouvement = true

    local tween = TweenService:Create(porte, TweenInfo.new(0.6), {CFrame = posOuverte})
    tween.Completed:Connect(function()
        estOuverte = true
        estEnMouvement = false  -- libère le verrou
    end)
    tween:Play()
end

local function fermer()
    if estEnMouvement or not estOuverte then return end
    estEnMouvement = true

    local tween = TweenService:Create(porte, TweenInfo.new(0.6), {CFrame = posFermee})
    tween.Completed:Connect(function()
        estOuverte = false
        estEnMouvement = false
    end)
    tween:Play()
end

porte.Touched:Connect(function(hit)
    if Players:GetPlayerFromCharacter(hit.Parent) then
        ouvrir()
    end
end)
porte.TouchEnded:Connect(function(hit)
    if Players:GetPlayerFromCharacter(hit.Parent) then
        task.delay(1, fermer)  -- ferme 1 seconde après que le joueur s'éloigne
    end
end)
Règle d'or — À chaque début de fonction d'action, vérifie l'état : if etatIncompatible then return end. Ça "verrouille" le système contre les actions contradictoires.
À toi de jouer — Reprends ton script de porte du chapitre 10. Ajoute les variables estOuverte et estEnMouvement et les gardes correspondantes. Essaie d'appuyer très vite plusieurs fois sur la Part : la porte ne devrait plus glitcher.
Chapitre 19 — Jour 14

Gérer plusieurs connexions qui interagissent

Un script réel combine souvent : un Touched, un Heartbeat, et un Tween.Completed. Sans organisation, ils se marchent dessus. Voici comment les gérer proprement.

-- Exemple : zone qui active une boucle Heartbeat, puis la coupe avec un Tween
local RunService = game:GetService("RunService")
local TweenService = game:GetService("TweenService")
local zone = script.Parent

-- Stocke TOUTES les connexions dans une table
local connexions = {}

local function couperTout()
    for _, c in ipairs(connexions) do
        if c then c:Disconnect() end
    end
    connexions = {}
end

-- Connexion 1 : détecter l'entrée dans la zone
connexions[1] = zone.Touched:Connect(function(hit)
    local hum = hit.Parent:FindFirstChildOfClass("Humanoid")
    if not hum then return end

    -- Connexion 2 : boucle qui tourne tant que le joueur est dans la zone
    local heartbeatConn
    heartbeatConn = RunService.Heartbeat:Connect(function(dt)
        if not hum or not hum.Parent then
            heartbeatConn:Disconnect()
            heartbeatConn = nil
            return
        end
        hum.WalkSpeed = 5  -- ralentit le joueur dans la zone
    end)
    table.insert(connexions, heartbeatConn)

    -- Connexion 3 : quitter la zone remet la vitesse à la normale
    connexions[#connexions + 1] = zone.TouchEnded:Connect(function(hitEnd)
        if hitEnd.Parent == hit.Parent then
            hum.WalkSpeed = 16
            if heartbeatConn then
                heartbeatConn:Disconnect()
                heartbeatConn = nil
            end
        end
    end)
end)

-- Nettoyage complet si le script est désactivé
script.Disabled:Connect(couperTout)
Bonnes pratiques
1. Stocke chaque :Connect() dans une variable nommée.
2. Avant de déconnecter, vérifie : if connexion then connexion:Disconnect() end.
3. Après Disconnect, mets à nil : connexion = nil. Ça libère la mémoire.
4. Groupe tes connexions dans une table pour pouvoir tout couper en une boucle.
À toi de jouer — Crée un script qui connecte simultanément un Heartbeat ET un Touched. Dans le Heartbeat, incrémente un compteur. Quand le Touched se déclenche, déconnecte le Heartbeat et affiche le nombre de frames qu'il a tournées.
Chapitre 20 — Jour 15

Lire du code avancé

Savoir lire du code que tu n'as pas écrit est plus difficile — et plus utile — que d'en écrire. Avant de lire l'explication ci-dessous, essaie d'analyser toi-même chaque bloc. Pose-toi : que fait cette ligne ? pourquoi est-elle là ?

Exercice 1 — Téléporteur avec cooldown : lis ce script et explique-le bloc par bloc avant de lire l'analyse. 
-- === CODE MYSTÈRE — lis d'abord, explique ensuite ===
local Players = game:GetService("Players")
local TweenService = game:GetService("TweenService")
local teleporteur = script.Parent
local destination = workspace:WaitForChild("Destination")

local cooldowns = {}
local DELAI = 3

teleporteur.Touched:Connect(function(hit)
    local joueur = Players:GetPlayerFromCharacter(hit.Parent)
    if not joueur then return end
    if cooldowns[joueur.UserId] then return end

    cooldowns[joueur.UserId] = true

    local character = joueur.Character
    local rootPart = character and character:FindFirstChild("HumanoidRootPart")
    if rootPart then
        rootPart.CFrame = destination.CFrame + Vector3.new(0, 3, 0)
    end

    task.delay(DELAI, function()
        cooldowns[joueur.UserId] = nil
    end)
end)

Players.PlayerRemoving:Connect(function(joueur)
    cooldowns[joueur.UserId] = nil
end)
Analyse ligne par ligne :
• Lignes 1–4 : on récupère les services et les deux Parts (le téléporteur et la destination).
• cooldowns = {} : table qui retient quels joueurs sont en cooldown (un dictionnaire clé=UserId).
• DELAI = 3 : constante nommée en MAJUSCULES — convention pour les valeurs fixes.
• if not joueur then return end : garde "pas un joueur → ignore".
• if cooldowns[joueur.UserId] then return end : garde "déjà en cooldown → ignore".
• rootPart.CFrame = destination.CFrame + Vector3.new(0, 3, 0) : téléporte en ajoutant 3 unités en Y pour que le joueur atterrisse au-dessus de la destination, pas dedans.
• task.delay : libère le cooldown dans 3 secondes sans bloquer le thread.
• PlayerRemoving : nettoyage mémoire quand le joueur quitte.
Exercice 2 — Perceuse qui creuse un mur 
-- === CODE MYSTÈRE 2 ===
local RunService = game:GetService("RunService")
local perceuse = script.Parent

local VITESSE = 4
local isMining = false
local connexionHB = nil

local function startMining()
    if isMining then return end
    isMining = true
    connexionHB = RunService.Heartbeat:Connect(function(dt)
        perceuse.CFrame = perceuse.CFrame * CFrame.new(0, 0, -VITESSE * dt)
        local parts = workspace:GetPartBoundsInBox(perceuse.CFrame, perceuse.Size)
        for _, p in ipairs(parts) do
            if p ~= perceuse and p.Name == "Mur" then
                p:Destroy()
            end
        end
    end)
end

local function stopMining()
    if not isMining then return end
    isMining = false
    if connexionHB then
        connexionHB:Disconnect()
        connexionHB = nil
    end
end

perceuse.Touched:Connect(function(hit)
    if hit.Name == "Bouton" then startMining() end
end)
perceuse.TouchEnded:Connect(function(hit)
    if hit.Name == "Bouton" then stopMining() end
end)
Analyse :
• VITESSE = 4 : 4 unités par seconde (multiplié par dt).
• isMining + if isMining then return end : state machine simple — interdit de démarrer deux fois.
• Dans Heartbeat : CFrame * CFrame.new(0,0,-VITESSE*dt) = avance dans la direction locale de la perceuse à vitesse constante.
• GetPartBoundsInBox : liste toutes les Parts qui se trouvent dans l'espace occupé par la perceuse.
• if p ~= perceuse and p.Name == "Mur" : ignore la perceuse elle-même, détruit les Parts nommées "Mur".
• stopMining : coupe le Heartbeat proprement via Disconnect + nil.
À toi de jouer — Dans Studio, colle le script de la perceuse dans une Part cylindrique. Crée des Parts nommées "Mur" dans sa trajectoire. Crée une Part nommée "Bouton". Lance le jeu et appuie sur le bouton : la perceuse devrait avancer et détruire les murs.
